## How I Can Help

I can assist with a wide range of software engineering tasks. Here are some examples of what I can do:

- **Code Analysis:** I can analyze the codebase to identify potential issues, suggest improvements, and explain complex parts of the code.
- **Code Implementation:** I can write new features, fix bugs, and implement unit and integration tests. I can also refactor existing code to improve its quality and performance.
- **Database Management:** I can help you write and manage database migrations using Flyway.
- **Build & Deployment:** I can help you create and manage your `build.gradle` file, as well as your `Dockerfile` and `docker-compose.yml` files.
- **Documentation:** I can create and update documentation, including the `README.md` file and this development plan.

## How to Work With Me Effectively

To get the most out of our collaboration, please follow these guidelines:

- **Be Specific and Task-Oriented:** Instead of broad requests, please provide specific, actionable tasks. For example:

    - **Bad:** "Fix the user profile page."
    - **Good:** "The user profile page is throwing a `NullPointerException` when a user who has not submitted any solutions views their profile. Please add a null check and display a message saying 'No submissions yet.'"

- **Provide Context:** When asking for help with a specific piece of code, please provide the relevant file paths and any other context that might be helpful. This will save us time and help me provide a more accurate and relevant response.

- **Refer to the Development Plan:** We have a detailed development plan in `DEVELOPMENT_PLAN.md`. When you're ready to work on a new task, you can refer to the plan and tell me which task you'd like to tackle next.

## Project Conventions

To ensure consistency and maintain a high level of code quality, we should adhere to the following conventions:

- **Coding Style:** We will follow the [Google Java Style Guide](https://google.github.io/styleguide/javaguide.html).
- **Commit Messages:** We will use the [Conventional Commits](https://www.conventionalcommits.org/) specification for our commit messages. This will help us maintain a clear and descriptive commit history.
- **Testing:** All new features must be accompanied by unit tests with a reasonable level of code coverage. All bug fixes must include a regression test.
